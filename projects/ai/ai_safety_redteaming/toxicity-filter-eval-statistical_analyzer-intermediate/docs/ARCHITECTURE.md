# Architecture (HLD) — Toxicity Filter Evaluator: Statistical Analyzer

## Problem & Users

Toxicity Filter Evaluator built as a Statistical analyzer. Toxicity filters screen model outputs before they reach users, and evaluating them needs adversarial edge cases: obfuscated slurs, reclaimed language, and benign text that looks toxic. Precision-recall curves across thresholds show the censorship-versus-safety tradeoff. The evaluator scores seeded tricky cases against a mock filter. Draws a seeded synthetic sample and reports count, mean, median, stdev, quartiles, and an ASCII histogram.

The intended user is a student or engineer working in ai (ai_safety_redteaming) who needs a working, runnable reference for Toxicity Filter Evaluator — something they can read end to end, run in seconds, and adapt to their own data or experiments.

## Data Flow

```
--seed -> generate_sample (mixture model)
sample -> summarize (sort, moments, percentiles, histogram)
summary -> print_report (table + ASCII histogram)
```

## Storage

In-memory only: the sample and summary exist for the duration of the run and nothing is persisted.

## Scaling & Limits

The sample is sorted in memory, so multi-million-point samples would need a streaming quantile sketch instead.

## Trade-offs

Hand-rolled statistics avoid dependencies but only cover univariate descriptives, not hypothesis tests or modeling.

## Failure Handling

An empty sample cannot occur (n comes from --samples), and a constant sample degrades gracefully to a single non-empty histogram bin.
