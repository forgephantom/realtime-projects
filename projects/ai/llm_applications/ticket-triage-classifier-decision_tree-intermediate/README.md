# Support Ticket Triage: Decision Tree Classifier

**Domain:** ai | **Subdomain:** llm_applications | **Difficulty:** intermediate | **Est. build time:** 4-8 hours

---

## Overview

Support Ticket Triage built as a Decision tree classifier. Ticket triage reads an incoming support request, assigns priority and category, and routes it to the right queue with a suggested first response. Priority scoring weighs urgency signals like outage language against customer tier. Misrouted tickets are the key metric, tracked per category in the simulation. Grows a Gini-based decision tree on seeded synthetic features, prints the tree as text, and reports test accuracy.

**Core concept — Support Ticket Triage:** Ticket triage reads an incoming support request, assigns priority and category, and routes it to the right queue with a suggested first response. Priority scoring weighs urgency signals like outage language against customer tier. Misrouted tickets are the key metric, tracked per category in the simulation.

**Why this matters in the real world:** Support platforms auto-route tickets so urgent issues reach the right team fast.

## Features

- **DecisionTree**: Binary decision tree grown with greedy Gini-impurity splits.
- `gini` (`gini(labels)`): Gini impurity of a label list.
- `majority` (`majority(labels)`): Most common label.
- `accuracy` (`accuracy(y_true, y_pred)`): Fraction of correct predictions.
- `generate_dataset` (`generate_dataset(seed, n)`): Generate 2-feature topic rows with binary labels.
- `DecisionTree.fit` (`DecisionTree.fit(self, X, y)`): Grow the tree from training features X and labels y.
- `DecisionTree.predict` (`DecisionTree.predict(self, X)`): Predict labels for feature vectors X.
- `print_tree` (`print_tree(node, depth=0)`): Print the tree structure as indented text.
- `main` (`main()`): Parse args, train, print the tree, and report accuracy.

## How It Works

The project is built around Greedy binary splits maximizing Gini impurity gain. Input data flows from src/main.py through the processing modules, and the overall approach runs in O(d * n^2) worst case to find splits for d features, n rows. See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) for the high-level design and [docs/DESIGN.md](docs/DESIGN.md) for the detailed module breakdown.
