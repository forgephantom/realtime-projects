# Architecture (HLD) — Long Context Evaluator: Eval_Harness

## Problem & Users

Long Context Evaluator built as a eval_harness. Long-context models are tested with needle-in-a-haystack retrieval: a fact is buried at varying depths in a long document and the model must find it. Performance typically degrades near the middle of the context, the lost-in-the-middle effect. The evaluator sweeps context length and needle depth to map the retrieval frontier. An evaluation harness that runs test cases against a stub model, measures accuracy and latency, and adds an LLM-as-judge rubric score per case.

The intended user is a student or engineer working in ai (model_evaluation) who needs a working, runnable reference for Long Context Evaluator — something they can read end to end, run in seconds, and adapt to their own data or experiments.

## Data Flow

```
test cases -> run_case (stub model + latency + exact match) -> results
results + rubric -> judge_score per case -> judged scores
results + judged -> summarize -> accuracy, latency, judge averages
```

## Storage

No persistence: cases, results, and summaries are regenerated from the seed each run.

## Scaling & Limits

Sequential runs suit hundreds of cases; thousands would want parallel workers and a persistent results store.

## Trade-offs

Exact-match correctness is strict and reproducible but penalizes correct answers phrased differently; the judge score softens that.

## Failure Handling

A stub model crash is caught per case and recorded as incorrect with the error text, so one bad case never kills the run.
