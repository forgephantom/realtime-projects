# Architecture (HLD) — Prompt Regression Test Suite: Eval_Harness

## Problem & Users

Prompt Regression Test Suite built as a eval_harness. Prompt changes can silently break previously correct outputs, so a regression suite re-runs a frozen set of prompts and compares new outputs against baselines. Semantic comparison catches meaning changes that string matching misses, and diff reports show exactly which cases regressed. A failing threshold gates deployment of the new prompt. An evaluation harness that runs test cases against a stub model, measures accuracy and latency, and adds an LLM-as-judge rubric score per case.

The intended user is a student or engineer working in ai (model_evaluation) who needs a working, runnable reference for Prompt Regression Test Suite — something they can read end to end, run in seconds, and adapt to their own data or experiments.

## Data Flow

```
test cases -> run_case (stub model + latency + exact match) -> results
results + rubric -> judge_score per case -> judged scores
results + judged -> summarize -> accuracy, latency, judge averages
```

## Storage

No persistence: cases, results, and summaries are regenerated from the seed each run.

## Scaling & Limits

Sequential runs suit hundreds of cases; thousands would want parallel workers and a persistent results store.

## Trade-offs

Exact-match correctness is strict and reproducible but penalizes correct answers phrased differently; the judge score softens that.

## Failure Handling

A stub model crash is caught per case and recorded as incorrect with the error text, so one bad case never kills the run.
