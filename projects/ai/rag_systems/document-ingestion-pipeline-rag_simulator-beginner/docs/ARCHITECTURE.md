# Architecture (HLD) — Document Ingestion Pipeline: Rag_Simulator

## Problem & Users

Document Ingestion Pipeline built as a rag_simulator. A document ingestion pipeline loads raw files, extracts clean text, splits it into chunks, and indexes the embeddings with metadata. Format handlers deal with PDFs, spreadsheets, and HTML quirks. Idempotent re-ingestion updates changed documents without duplicating the index. A retrieval-augmented generation pipeline simulator that chunks documents, retrieves passages with TF-IDF-style scoring, and answers extractively with citations.

The intended user is a student or engineer working in ai (rag_systems) who needs a working, runnable reference for Document Ingestion Pipeline — something they can read end to end, run in seconds, and adapt to their own data or experiments.

## Data Flow

```
documents -> chunk_documents (size/overlap) -> chunks
chunks -> IDF table -> score_chunk per query -> retrieve top-k
top chunk -> generate_answer -> answer text + citation
```

## Storage

No persistence: the corpus, chunks, and IDF table are rebuilt from the seed on every run.

## Scaling & Limits

In-memory chunk list suits thousands of chunks; millions would need an inverted index instead of per-query rescoring.

## Trade-offs

Term overlap is transparent and fast but misses paraphrases that embedding retrieval would catch.

## Failure Handling

A query with no overlapping terms scores zero everywhere and returns a graceful 'no relevant passage' answer instead of guessing.
