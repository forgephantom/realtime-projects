# Architecture (HLD) — Scenario Model Comparator: Financial_Model

## Problem & Users

Scenario Model Comparator built as a financial_model. Scenario modeling reruns the same financial model under base, upside, and downside assumptions to bound the outcome range. The discipline is keeping scenarios internally consistent: a downside case cannot assume strong pricing and weak volume at once. Comparing scenario outputs shows which decisions are robust and which bet everything on one future. A financial modeler computing NPV, IRR by bisection, DCF valuation, break-even point, and a loan amortization schedule from seeded synthetic inputs.

The intended user is a student or engineer working in business_analyst (financial_modeling) who needs a working, runnable reference for Scenario Model Comparator — something they can read end to end, run in seconds, and adapt to their own data or experiments.

## Data Flow

```
seeded inputs -> cashflows, loan terms, unit economics
cashflows -> npv(rate) -> present value
cashflows -> irr (bisection) -> discount rate where NPV=0
cashflows -> dcf_value -> enterprise value with terminal value
unit economics -> breakeven -> units to cover fixed costs
loan terms -> amortization_schedule -> monthly payment table
```

## Storage

No persistence: inputs and schedules are regenerated from the seed each run.

## Scaling & Limits

Closed-form math suits any horizon; portfolio-scale use would vectorize across many projects.

## Trade-offs

Deterministic formulas are auditable but ignore taxes, inflation, and risk beyond the discount rate.

## Failure Handling

IRR raises a clear error when NPV has no sign change in the search range instead of returning a bogus rate.
