# Cycle Time Analyzer: Statistical Analyzer

**Domain:** business_analyst | **Subdomain:** process_modeling | **Difficulty:** beginner | **Est. build time:** 2-4 hours

---

## Overview

Cycle Time Analyzer built as a Statistical analyzer. Cycle time analysis breaks lead time into processing, waiting, and rework components per step. Waiting usually dominates, which means capacity is rarely the real problem. The analyzer quantifies each component and shows where a small change buys the most time. Draws a seeded synthetic sample and reports count, mean, median, stdev, quartiles, and an ASCII histogram.

**Core concept — Cycle Time Analyzer:** Cycle time analysis breaks lead time into processing, waiting, and rework components per step. Waiting usually dominates, which means capacity is rarely the real problem. The analyzer quantifies each component and shows where a small change buys the most time.

**Why this matters in the real world:** Service operations teams analyze cycle time to cut customer wait in claims and onboarding.

---

## Features

- `generate_sample` (`generate_sample(seed, n)`): Draw synthetic topic measurements (mixture model).
- `percentile` (`percentile(sorted_vals, q)`): Linear-interpolation percentile of a pre-sorted list.
- `summarize` (`summarize(values, bins)`): Compute a full descriptive-statistics summary.
- `print_report` (`print_report(summary)`): Print the summary table and ASCII histogram.
- `main` (`main()`): Parse args and print the report.

## How It Works

The project is built around Descriptive statistics with linear-interpolation percentiles. Input data flows from src/main.py through the processing modules, and the overall approach runs in O(n log n) for the sort; O(n) for the histogram pass. See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) for the high-level design and [docs/DESIGN.md](docs/DESIGN.md) for the detailed module breakdown.
