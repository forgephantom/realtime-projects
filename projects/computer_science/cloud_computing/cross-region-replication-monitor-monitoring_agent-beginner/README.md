# Cross Region Replication Monitor: Monitoring Agent

**Domain:** computer_science | **Subdomain:** cloud_computing | **Difficulty:** beginner | **Est. build time:** 2-4 hours

---

## Overview

Cross Region Replication Monitor built as a Monitoring agent. Cross-region replication gives disaster recovery, but lag determines data loss on failover. The monitor tracks replication lag, backlog, and throughput per region pair, alerting before lag exceeds RPO. It watches the safety net. Samples synthetic topic metrics for N cycles, evaluates each reading against thresholds, prints readings and alerts.

**Core concept — Cross Region Replication Monitor:** Cross-region replication gives disaster recovery, but lag determines data loss on failover. The monitor tracks replication lag, backlog, and throughput per region pair, alerting before lag exceeds RPO. It watches the safety net.

**Why this matters in the real world:** Used by DR teams.

---

## Features

- **Monitor**: Samples metrics, evaluates thresholds, and collects alerts.
- `read_metrics` (`read_metrics(rng, cycle)`): Sample one synthetic topic metric reading.
- `check_thresholds` (`check_thresholds(reading, thresholds)`): Return a list of alert strings for readings over threshold.
- `Monitor.run` (`Monitor.run(self, cycles, interval)`): Sample `cycles` readings, print them, return alert count.
- `main` (`main()`): Parse args and run the monitor.

## How It Works

The project is built around Periodic sampling with static threshold evaluation. Input data flows from src/main.py through the processing modules, and the overall approach runs in O(cycles) total; O(1) per sample. See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) for the high-level design and [docs/DESIGN.md](docs/DESIGN.md) for the detailed module breakdown.
