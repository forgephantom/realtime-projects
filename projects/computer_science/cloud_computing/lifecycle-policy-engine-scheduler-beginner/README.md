# Lifecycle Policy Engine: Task Scheduler

**Domain:** computer_science | **Subdomain:** cloud_computing | **Difficulty:** beginner | **Est. build time:** 2-4 hours

---

## Overview

Lifecycle Policy Engine built as a Task scheduler. Storage lifecycle policies move aging data to cheaper tiers and eventually delete it. The engine applies rules to object inventories, projecting cost savings and flagging premature transitions. Tiering automation with guardrails. Registers interval jobs on a heap scheduler, runs them for a fixed demo duration, and prints the execution log.

**Core concept — Lifecycle Policy Engine:** Storage lifecycle policies move aging data to cheaper tiers and eventually delete it. The engine applies rules to object inventories, projecting cost savings and flagging premature transitions. Tiering automation with guardrails.

**Why this matters in the real world:** Used managing storage costs.

---

## Features

- **Scheduler**: Minimal interval scheduler driven by a heap of next-run times.
- `make_demo_job` (`make_demo_job(tag)`): Build a demo job function that counts its own executions.
- `Scheduler.add_job` (`Scheduler.add_job(self, name, interval, func)`): Register `func` to run every `interval` seconds under `name`.
- `Scheduler.run` (`Scheduler.run(self, duration)`): Run scheduled jobs for `duration` seconds; return the log.
- `main` (`main()`): Parse args, register demo jobs, run, and print the log.

## How It Works

The project is built around Heap-ordered next-run-time scheduling loop. Input data flows from src/main.py through the processing modules, and the overall approach runs in O(log j) per execution for j jobs. See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) for the high-level design and [docs/DESIGN.md](docs/DESIGN.md) for the detailed module breakdown.
