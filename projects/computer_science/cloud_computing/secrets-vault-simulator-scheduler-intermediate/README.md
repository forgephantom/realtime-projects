# Secrets Vault Simulator: Task Scheduler

**Domain:** computer_science | **Subdomain:** cloud_computing | **Difficulty:** intermediate | **Est. build time:** 4-8 hours

---

## Overview

Secrets Vault Simulator built as a Task scheduler. Central secret vaults broker access with leases, rotation, and audit, instead of scattering credentials. The simulator models secret engines, dynamic credentials with TTLs, and revocation. It shows the operational pattern behind Vault-style systems. Registers interval jobs on a heap scheduler, runs them for a fixed demo duration, and prints the execution log.

**Core concept — Secrets Vault Simulator:** Central secret vaults broker access with leases, rotation, and audit, instead of scattering credentials. The simulator models secret engines, dynamic credentials with TTLs, and revocation. It shows the operational pattern behind Vault-style systems.

**Why this matters in the real world:** Used learning secrets management.

---

## Features

- **Scheduler**: Minimal interval scheduler driven by a heap of next-run times.
- `make_demo_job` (`make_demo_job(tag)`): Build a demo job function that counts its own executions.
- `Scheduler.add_job` (`Scheduler.add_job(self, name, interval, func)`): Register `func` to run every `interval` seconds under `name`.
- `Scheduler.run` (`Scheduler.run(self, duration)`): Run scheduled jobs for `duration` seconds; return the log.
- `main` (`main()`): Parse args, register demo jobs, run, and print the log.

## How It Works

The project is built around Heap-ordered next-run-time scheduling loop. Input data flows from src/main.py through the processing modules, and the overall approach runs in O(log j) per execution for j jobs. See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) for the high-level design and [docs/DESIGN.md](docs/DESIGN.md) for the detailed module breakdown.
