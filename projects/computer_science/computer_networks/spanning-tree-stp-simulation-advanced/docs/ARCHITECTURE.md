# Architecture (HLD) — Spanning Tree (STP-lite): Simulation (Logistic Growth)

## Problem & Users

Spanning Tree (STP-lite) built as a Simulation (logistic growth). STP prevents L2 loops by electing a root bridge and blocking redundant ports: the lite version runs the election, computes port roles, and reconverges on link failure. It trades convergence speed for loop-freedom. The demo shows the blocked ports that save the LAN. Euler-integrates logistic growth dP/dt = r*P*(1-P/K) and prints the trajectory table with summary statistics.

The intended user is a student or engineer working in computer_science (computer_networks) who needs a working, runnable reference for Spanning Tree (STP-lite) — something they can read end to end, run in seconds, and adapt to their own data or experiments.

## Data Flow

```
PARAMS (r, K, P0) + --steps/--dt -> simulate (Euler loop)
trajectory rows -> print_trajectory (sampled table)
rows -> start/end/peak summary
```

## Storage

In-memory only: the trajectory list exists for the run and is not persisted.

## Scaling & Limits

The trajectory is a plain list, so millions of steps would use noticeable memory; streaming or downsampling would fix that.

## Trade-offs

Explicit Euler is the simplest integrator to read and verify, at the cost of accuracy versus higher-order methods for stiff dynamics.

## Failure Handling

A non-positive carrying capacity K would flip the growth sign; the template documents K as positive and the default params keep it well-behaved.
