# Architecture (HLD) — Endpoint Process Behavior Profiler: Statistical Analyzer

## Problem & Users

Endpoint Process Behavior Profiler built as a Statistical analyzer. Malware often hides behind legitimate process names while behaving abnormally, spawning odd children or touching unusual files. The profiler builds a baseline of normal parent-child process trees, file access, and network behavior per host, then flags processes that deviate. It focuses on behavior rather than signatures, catching novel threats. Draws a seeded synthetic sample and reports count, mean, median, stdev, quartiles, and an ASCII histogram.

The intended user is a student or engineer working in computer_science (cybersecurity) who needs a working, runnable reference for Endpoint Process Behavior Profiler — something they can read end to end, run in seconds, and adapt to their own data or experiments.

## Data Flow

```
--seed -> generate_sample (mixture model)
sample -> summarize (sort, moments, percentiles, histogram)
summary -> print_report (table + ASCII histogram)
```

## Storage

In-memory only: the sample and summary exist for the duration of the run and nothing is persisted.

## Scaling & Limits

The sample is sorted in memory, so multi-million-point samples would need a streaming quantile sketch instead.

## Trade-offs

Hand-rolled statistics avoid dependencies but only cover univariate descriptives, not hypothesis tests or modeling.

## Failure Handling

An empty sample cannot occur (n comes from --samples), and a constant sample degrades gracefully to a single non-empty histogram bin.
