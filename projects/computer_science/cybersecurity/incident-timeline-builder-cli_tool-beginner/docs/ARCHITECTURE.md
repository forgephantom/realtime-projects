# Architecture (HLD) — Incident Timeline Builder: Command-Line Tool

## Problem & Users

Incident Timeline Builder built as a Command-line tool. Incident response lives or dies on a clear timeline of who did what when, assembled from firewall, auth, EDR, and ticket logs. The builder normalizes timestamps across sources, merges events into one chronological view, and highlights gaps and bursts. Analysts annotate the timeline as the investigation proceeds, and it exports into the postmortem. A subcommand CLI that generates seeded synthetic topic rows and reports summaries, top-N rows, or filtered rows as tables or JSON.

The intended user is a student or engineer working in computer_science (cybersecurity) who needs a working, runnable reference for Incident Timeline Builder — something they can read end to end, run in seconds, and adapt to their own data or experiments.

## Data Flow

```
--seed -> generate_rows (synthetic table)
subcommand: summary | top | filter -> formatted table or JSON
```

## Storage

No persistence: rows are regenerated from the seed on every invocation and nothing is written to disk.

## Scaling & Limits

Rows live in a Python list, so memory grows linearly with --rows; fine for tens of thousands of rows on a laptop.

## Trade-offs

Synthetic seeded data keeps the tool self-contained and reproducible, at the cost of not reading real input files.

## Failure Handling

An empty filter result prints a zero-count table rather than erroring; --top-n larger than the row count simply returns all rows.
