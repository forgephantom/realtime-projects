# Architecture (HLD) — MFA Adoption Tracker: Statistical Analyzer

## Problem & Users

MFA Adoption Tracker built as a Statistical analyzer. Accounts without multi-factor authentication are the first to fall in credential attacks, so tracking enrollment matters. The tracker inventories users with their MFA status, method strength, and last verification, then reports adoption rates by team and names the holdouts. It also flags weak methods like SMS where stronger options exist. Draws a seeded synthetic sample and reports count, mean, median, stdev, quartiles, and an ASCII histogram.

The intended user is a student or engineer working in computer_science (cybersecurity) who needs a working, runnable reference for MFA Adoption Tracker — something they can read end to end, run in seconds, and adapt to their own data or experiments.

## Data Flow

```
--seed -> generate_sample (mixture model)
sample -> summarize (sort, moments, percentiles, histogram)
summary -> print_report (table + ASCII histogram)
```

## Storage

In-memory only: the sample and summary exist for the duration of the run and nothing is persisted.

## Scaling & Limits

The sample is sorted in memory, so multi-million-point samples would need a streaming quantile sketch instead.

## Trade-offs

Hand-rolled statistics avoid dependencies but only cover univariate descriptives, not hypothesis tests or modeling.

## Failure Handling

An empty sample cannot occur (n comes from --samples), and a constant sample degrades gracefully to a single non-empty histogram bin.
