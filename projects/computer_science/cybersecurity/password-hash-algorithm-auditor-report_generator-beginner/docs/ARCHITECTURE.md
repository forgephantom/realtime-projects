# Architecture (HLD) — Password Hash Algorithm Auditor: Report Generator

## Problem & Users

Password Hash Algorithm Auditor built as a report generator. Storing passwords with fast hashes like MD5 or SHA-256 lets attackers test billions of guesses per second after a breach, while memory-hard functions like Argon2id and bcrypt slow them dramatically. This auditor inspects a password database dump format, identifies the algorithm and parameters behind each hash prefix, and flags anything below the current policy bar. It never cracks anything; it grades the storage hygiene. A report generator that builds seeded synthetic data, aggregates it, and writes a Markdown report with summary and per-service tables.

The intended user is a student or engineer working in computer_science (cybersecurity) who needs a working, runnable reference for Password Hash Algorithm Auditor — something they can read end to end, run in seconds, and adapt to their own data or experiments.

## Data Flow

```
seeded RNG -> generate_records -> list of measurement dicts
records -> summarize -> totals, per-service rollups, error rate
summary + sample rows -> render_markdown -> demo_output/report.md
```

## Storage

Writes one Markdown file under ./demo_output; nothing else is persisted.

## Scaling & Limits

Holds all records in memory; millions of rows would want streaming aggregation instead.

## Trade-offs

Hand-rolled Markdown keeps the demo dependency-free; a real reporting tool might use a templating engine.

## Failure Handling

No external input is parsed, so there is nothing malformed to handle; write errors propagate as normal OSErrors.
