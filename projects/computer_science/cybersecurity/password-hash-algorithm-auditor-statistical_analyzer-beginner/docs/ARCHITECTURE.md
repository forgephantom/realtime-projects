# Architecture (HLD) — Password Hash Algorithm Auditor: Statistical Analyzer

## Problem & Users

Password Hash Algorithm Auditor built as a Statistical analyzer. Storing passwords with fast hashes like MD5 or SHA-256 lets attackers test billions of guesses per second after a breach, while memory-hard functions like Argon2id and bcrypt slow them dramatically. This auditor inspects a password database dump format, identifies the algorithm and parameters behind each hash prefix, and flags anything below the current policy bar. It never cracks anything; it grades the storage hygiene. Draws a seeded synthetic sample and reports count, mean, median, stdev, quartiles, and an ASCII histogram.

The intended user is a student or engineer working in computer_science (cybersecurity) who needs a working, runnable reference for Password Hash Algorithm Auditor — something they can read end to end, run in seconds, and adapt to their own data or experiments.

## Data Flow

```
--seed -> generate_sample (mixture model)
sample -> summarize (sort, moments, percentiles, histogram)
summary -> print_report (table + ASCII histogram)
```

## Storage

In-memory only: the sample and summary exist for the duration of the run and nothing is persisted.

## Scaling & Limits

The sample is sorted in memory, so multi-million-point samples would need a streaming quantile sketch instead.

## Trade-offs

Hand-rolled statistics avoid dependencies but only cover univariate descriptives, not hypothesis tests or modeling.

## Failure Handling

An empty sample cannot occur (n comes from --samples), and a constant sample degrades gracefully to a single non-empty histogram bin.
