# Architecture (HLD) — Rogue DHCP Detector: Simulation (Logistic Growth)

## Problem & Users

Rogue DHCP Detector built as a Simulation (logistic growth). A rogue DHCP server hands out malicious gateway and DNS settings, silently rerouting a LAN's traffic through the attacker. The detector listens for DHCP offers and compares responding server identities against the authorized list, flagging any unknown server instantly. It also watches for offers with suspiciously short leases or odd options. Euler-integrates logistic growth dP/dt = r*P*(1-P/K) and prints the trajectory table with summary statistics.

The intended user is a student or engineer working in computer_science (cybersecurity) who needs a working, runnable reference for Rogue DHCP Detector — something they can read end to end, run in seconds, and adapt to their own data or experiments.

## Data Flow

```
PARAMS (r, K, P0) + --steps/--dt -> simulate (Euler loop)
trajectory rows -> print_trajectory (sampled table)
rows -> start/end/peak summary
```

## Storage

In-memory only: the trajectory list exists for the run and is not persisted.

## Scaling & Limits

The trajectory is a plain list, so millions of steps would use noticeable memory; streaming or downsampling would fix that.

## Trade-offs

Explicit Euler is the simplest integrator to read and verify, at the cost of accuracy versus higher-order methods for stiff dynamics.

## Failure Handling

A non-positive carrying capacity K would flip the growth sign; the template documents K as positive and the default params keep it well-behaved.
