# Architecture (HLD) — Secrets in Code Scanner: Command-Line Tool

## Problem & Users

Secrets in Code Scanner built as a Command-line tool. API keys and passwords committed to repositories get scraped by attackers within minutes of a public push. The scanner walks a codebase looking for high-entropy strings, known key prefixes, and assignment patterns like password equals, then filters out test fixtures and placeholders. Findings include the file, line, and secret type so rotation can start immediately. A subcommand CLI that generates seeded synthetic topic rows and reports summaries, top-N rows, or filtered rows as tables or JSON.

The intended user is a student or engineer working in computer_science (cybersecurity) who needs a working, runnable reference for Secrets in Code Scanner — something they can read end to end, run in seconds, and adapt to their own data or experiments.

Each component maps to a real module in the project; no box in this design is aspirational — everything named here exists in the source tree.

## Data Flow

```
--seed -> generate_rows (synthetic table)
subcommand: summary | top | filter -> formatted table or JSON
```

## Storage

No persistence: rows are regenerated from the seed on every invocation and nothing is written to disk.

## Scaling & Limits

Rows live in a Python list, so memory grows linearly with --rows; fine for tens of thousands of rows on a laptop.

## Trade-offs

Synthetic seeded data keeps the tool self-contained and reproducible, at the cost of not reading real input files.

## Failure Handling

An empty filter result prints a zero-count table rather than erroring; --top-n larger than the row count simply returns all rows.
