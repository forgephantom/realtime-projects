# Metric Anomaly Detector: Monitoring Agent

**Domain:** computer_science | **Subdomain:** data_engineering | **Difficulty:** intermediate | **Est. build time:** 4-8 hours

---

## Overview

Metric Anomaly Detector built as a Monitoring agent. Business metrics like signups or revenue deserve anomaly detection tuned to seasonality. The detector decomposes trend and weekly patterns flagging residual outliers. It pages on the real drops, not the weekend dips. Samples synthetic topic metrics for N cycles, evaluates each reading against thresholds, prints readings and alerts.

**Core concept — Metric Anomaly Detector:** Business metrics like signups or revenue deserve anomaly detection tuned to seasonality. The detector decomposes trend and weekly patterns flagging residual outliers. It pages on the real drops, not the weekend dips.

**Why this matters in the real world:** Used by data teams watching business health.

---

## Features

- **Monitor**: Samples metrics, evaluates thresholds, and collects alerts.
- `read_metrics` (`read_metrics(rng, cycle)`): Sample one synthetic topic metric reading.
- `check_thresholds` (`check_thresholds(reading, thresholds)`): Return a list of alert strings for readings over threshold.
- `Monitor.run` (`Monitor.run(self, cycles, interval)`): Sample `cycles` readings, print them, return alert count.
- `main` (`main()`): Parse args and run the monitor.

## How It Works

The project is built around Periodic sampling with static threshold evaluation. Input data flows from src/main.py through the processing modules, and the overall approach runs in O(cycles) total; O(1) per sample. See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) for the high-level design and [docs/DESIGN.md](docs/DESIGN.md) for the detailed module breakdown.
