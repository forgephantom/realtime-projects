# Presentation Guide — A/B Test Designer: Statistical Analyzer

## 60-Second Pitch

A A/B Test Designer statistics tool that turns a seeded synthetic sample into a full descriptive report with quartiles and an ASCII histogram. Designing an A/B test means picking the metric, minimum detectable effect, power, and significance, then computing required sample size and runtime from traffic.

A/B Test Designer in two sentences: Designing an A/B test means picking the metric, minimum detectable effect, power, and significance, then computing required sample size and runtime from traffic. The designer also plans ramp schedules and guardrail metrics. Skipping this step is how teams run inconclusive tests for months.

## Architecture Talking Points

- Components: a single module plus the CLI entrypoint — each maps to a real module in `src/`, and the data-flow diagram shows how they connect.
- Algorithm: Descriptive statistics with linear-interpolation percentiles; runs in O(n log n) for the sort; O(n) for the histogram pass.
- Honest scaling limit: The sample is sorted in memory, so multi-million-point samples would need a streaming quantile sketch instead.

Use these when someone asks "how does it work?" — start with the problem, then walk the data flow, then name one trade-off. Trade-offs are what interviewers remember.

## Interview Q&A

**Q:** What distribution does the sample follow?

**A:** A two-component Gaussian mixture, which gives the histogram a visible bimodal shape instead of a flat bell curve.

**Q:** Are the sample size and bins configurable?

**A:** Yes; pass --samples and --bins to control the draw size and histogram resolution.

**Q:** Does it save the report anywhere?

**A:** No; it prints to stdout only, so results can be redirected or piped freely.
