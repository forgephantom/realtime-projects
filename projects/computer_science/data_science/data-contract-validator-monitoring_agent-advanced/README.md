# Data Contract Validator: Monitoring Agent

**Domain:** computer_science | **Subdomain:** data_science | **Difficulty:** advanced | **Est. build time:** 8-16 hours

---

## Overview

Data Contract Validator built as a Monitoring agent. Data contracts are executable agreements between producers and consumers: the validator checks schemas, value ranges, freshness, and volume against the contract on every batch, quarantining violations. Contract versioning manages evolution. It moves data quality left, to the producer. Samples synthetic topic metrics for N cycles, evaluates each reading against thresholds, prints readings and alerts.

**Core concept — Data Contract Validator:** Data contracts are executable agreements between producers and consumers: the validator checks schemas, value ranges, freshness, and volume against the contract on every batch, quarantining violations. Contract versioning manages evolution. It moves data quality left, to the producer.

**Why this matters in the real world:** Great Expectations, dbt contracts, and data-mesh contracts enforce producer agreements.

---

## Features

- **Monitor**: Samples metrics, evaluates thresholds, and collects alerts.
- `read_metrics` (`read_metrics(rng, cycle)`): Sample one synthetic topic metric reading.
- `check_thresholds` (`check_thresholds(reading, thresholds)`): Return a list of alert strings for readings over threshold.
- `Monitor.run` (`Monitor.run(self, cycles, interval)`): Sample `cycles` readings, print them, return alert count.
- `main` (`main()`): Parse args and run the monitor.

## How It Works

The project is built around Periodic sampling with static threshold evaluation. Input data flows from src/main.py through the processing modules, and the overall approach runs in O(cycles) total; O(1) per sample. See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) for the high-level design and [docs/DESIGN.md](docs/DESIGN.md) for the detailed module breakdown.
