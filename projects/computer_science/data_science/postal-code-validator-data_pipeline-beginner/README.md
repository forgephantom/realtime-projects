# Postal Code Validator: Data Pipeline (Etl)

**Domain:** computer_science | **Subdomain:** data_science | **Difficulty:** beginner | **Est. build time:** 2-4 hours

---

## Overview

Postal Code Validator built as a Data pipeline (ETL). Postal codes follow country patterns: the validator checks formats per country (US ZIP+4, UK outward/inward, Canadian ANA NAN), normalizes spacing and case, and maps codes to regions for analysis. Invalid codes get specific reasons, not just rejections. Extracts synthetic topic records, transforms them (drop invalid, normalize, bucket), and loads the clean set to CSV.

**Core concept — Postal Code Validator:** Postal codes follow country patterns: the validator checks formats per country (US ZIP+4, UK outward/inward, Canadian ANA NAN), normalizes spacing and case, and maps codes to regions for analysis. Invalid codes get specific reasons, not just rejections.

**Why this matters in the real world:** Address validation, geo-analysis, and shipping systems validate postal formats.

---

## Features

- **Pipeline**: Three-stage ETL pipeline for topic records.
- `generate_raw` (`generate_raw(seed, n)`): Extract stage: build synthetic raw records.
- `clean_rows` (`clean_rows(rows)`): Transform stage: drop invalid rows, normalize, bucket. Returns (clean_rows, dropped_count).
- `write_csv` (`write_csv(path, rows)`): Load stage: write rows to a CSV file.
- `Pipeline.extract` (`Pipeline.extract(self, n)`): Run the extract stage and return raw rows.
- `Pipeline.transform` (`Pipeline.transform(self, rows)`): Run the transform stage and return (clean, dropped).
- `Pipeline.load` (`Pipeline.load(self, rows)`): Run the load stage; return the CSV path written.
- `Pipeline.run` (`Pipeline.run(self, n)`): Run extract -> transform -> load; print a stage report.
- `main` (`main()`): Parse args and run the pipeline.
