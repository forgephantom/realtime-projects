# Architecture (HLD) — Slowly Changing Dimension (Type 2) Loader: Report Generator

## Problem & Users

Slowly Changing Dimension (Type 2) Loader built as a report generator. Type 2 SCDs preserve history: on attribute change, the loader closes the current row (end-date) and inserts a new version with a surrogate key, keeping effective date ranges gapless. Current-flag queries stay fast. It is the standard for auditable dimensions. A report generator that builds seeded synthetic data, aggregates it, and writes a Markdown report with summary and per-service tables.

The intended user is a student or engineer working in computer_science (data_science) who needs a working, runnable reference for Slowly Changing Dimension (Type 2) Loader — something they can read end to end, run in seconds, and adapt to their own data or experiments.

## Data Flow

```
seeded RNG -> generate_records -> list of measurement dicts
records -> summarize -> totals, per-service rollups, error rate
summary + sample rows -> render_markdown -> demo_output/report.md
```

## Storage

Writes one Markdown file under ./demo_output; nothing else is persisted.

## Scaling & Limits

Holds all records in memory; millions of rows would want streaming aggregation instead.

## Trade-offs

Hand-rolled Markdown keeps the demo dependency-free; a real reporting tool might use a templating engine.

## Failure Handling

No external input is parsed, so there is nothing malformed to handle; write errors propagate as normal OSErrors.
