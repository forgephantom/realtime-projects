# Architecture (HLD) — Text Cleaning Pipeline: Statistical Analyzer

## Problem & Users

Text Cleaning Pipeline built as a Statistical analyzer. Text preprocessing chains steps: lowercase, strip HTML/URLs, normalize unicode, remove stopwords, stem or lemmatize. Order matters (strip HTML before tokenizing). The pipeline is configurable per task because aggressive cleaning can destroy signal (e.g., in sentiment). Each step is inspectable. Draws a seeded synthetic sample and reports count, mean, median, stdev, quartiles, and an ASCII histogram.

The intended user is a student or engineer working in computer_science (data_science) who needs a working, runnable reference for Text Cleaning Pipeline — something they can read end to end, run in seconds, and adapt to their own data or experiments.

## Data Flow

```
--seed -> generate_sample (mixture model)
sample -> summarize (sort, moments, percentiles, histogram)
summary -> print_report (table + ASCII histogram)
```

## Storage

In-memory only: the sample and summary exist for the duration of the run and nothing is persisted.

## Scaling & Limits

The sample is sorted in memory, so multi-million-point samples would need a streaming quantile sketch instead.

## Trade-offs

Hand-rolled statistics avoid dependencies but only cover univariate descriptives, not hypothesis tests or modeling.

## Failure Handling

An empty sample cannot occur (n comes from --samples), and a constant sample degrades gracefully to a single non-empty histogram bin.
