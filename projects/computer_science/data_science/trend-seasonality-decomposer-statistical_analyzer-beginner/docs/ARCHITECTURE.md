# Architecture (HLD) — Trend-Seasonality Decomposer: Statistical Analyzer

## Problem & Users

Trend-Seasonality Decomposer built as a Statistical analyzer. Classical decomposition separates trend, seasonal, and residual with moving averages: the trend smooths, seasonal averages by period position, and the residual holds the unexplained. Strength metrics quantify how seasonal or trended a series is. It is the EDA starting point for time series. Draws a seeded synthetic sample and reports count, mean, median, stdev, quartiles, and an ASCII histogram.

The intended user is a student or engineer working in computer_science (data_science) who needs a working, runnable reference for Trend-Seasonality Decomposer — something they can read end to end, run in seconds, and adapt to their own data or experiments.

## Data Flow

```
--seed -> generate_sample (mixture model)
sample -> summarize (sort, moments, percentiles, histogram)
summary -> print_report (table + ASCII histogram)
```

## Storage

In-memory only: the sample and summary exist for the duration of the run and nothing is persisted.

## Scaling & Limits

The sample is sorted in memory, so multi-million-point samples would need a streaming quantile sketch instead.

## Trade-offs

Hand-rolled statistics avoid dependencies but only cover univariate descriptives, not hypothesis tests or modeling.

## Failure Handling

An empty sample cannot occur (n comes from --samples), and a constant sample degrades gracefully to a single non-empty histogram bin.
