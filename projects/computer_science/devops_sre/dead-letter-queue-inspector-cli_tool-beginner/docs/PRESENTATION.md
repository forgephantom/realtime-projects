# Presentation Guide — Dead Letter Queue Inspector: Command-Line Tool

## 60-Second Pitch

A Dead Letter Queue Inspector command-line tool with summary, top-N, and filter subcommands that works on reproducible seeded data and emits tables or JSON. Messages that fail repeatedly land in the dead letter queue, where they wait for someone to care.

Dead Letter Queue Inspector in two sentences: Messages that fail repeatedly land in the dead letter queue, where they wait for someone to care. The inspector samples DLQ contents, classifies failure reasons like poison payloads versus downstream outages, and supports replay after fixes. DLQs stop being write-only.

## Architecture Talking Points

- Components: a single module plus the CLI entrypoint — each maps to a real module in `src/`, and the data-flow diagram shows how they connect.
- Algorithm: Deterministic synthetic rows + subcommand dispatch; runs in O(n) to generate rows; O(n log n) for top-N sort.
- Honest scaling limit: Rows live in a Python list, so memory grows linearly with --rows; fine for tens of thousands of rows on a laptop.

Use these when someone asks "how does it work?" — start with the problem, then walk the data flow, then name one trade-off. Trade-offs are what interviewers remember.

## Interview Q&A

**Q:** What runs when no subcommand is given?

**A:** It prints the summary table, so `python3 src/main.py` alone is a complete demo.

**Q:** Can it output JSON?

**A:** Yes; pass --json to get machine-readable output from any subcommand.

**Q:** How does it handle large row counts?

**A:** Increase --rows; filtering and sorting stay linear-ish and the tool prints the first 20 filtered rows with a remainder count.
