# Heartbeat Monitor: Monitoring Agent

**Domain:** computer_science | **Subdomain:** devops_sre | **Difficulty:** beginner | **Est. build time:** 2-4 hours

---

## Overview

Heartbeat Monitor built as a Monitoring agent. The simplest liveness check is a periodic I am alive message, and missing heartbeats mean investigate. The monitor tracks last-seen timestamps per component, alerts after missed beats, and distinguishes a dead process from a slow network with grace periods. Simple, but everything depends on it. Samples synthetic topic metrics for N cycles, evaluates each reading against thresholds, prints readings and alerts.

**Core concept — Heartbeat Monitor:** The simplest liveness check is a periodic I am alive message, and missing heartbeats mean investigate. The monitor tracks last-seen timestamps per component, alerts after missed beats, and distinguishes a dead process from a slow network with grace periods. Simple, but everything depends on it.

**Why this matters in the real world:** Used as the liveness foundation in small systems.

---

## Features

- **Monitor**: Samples metrics, evaluates thresholds, and collects alerts.
- `read_metrics` (`read_metrics(rng, cycle)`): Sample one synthetic topic metric reading.
- `check_thresholds` (`check_thresholds(reading, thresholds)`): Return a list of alert strings for readings over threshold.
- `Monitor.run` (`Monitor.run(self, cycles, interval)`): Sample `cycles` readings, print them, return alert count.
- `main` (`main()`): Parse args and run the monitor.

## How It Works

The project is built around Periodic sampling with static threshold evaluation. Input data flows from src/main.py through the processing modules, and the overall approach runs in O(cycles) total; O(1) per sample. See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) for the high-level design and [docs/DESIGN.md](docs/DESIGN.md) for the detailed module breakdown.
