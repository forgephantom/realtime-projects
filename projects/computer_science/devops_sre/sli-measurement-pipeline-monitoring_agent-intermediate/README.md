# SLI Measurement Pipeline: Monitoring Agent

**Domain:** computer_science | **Subdomain:** devops_sre | **Difficulty:** intermediate | **Est. build time:** 4-8 hours

---

## Overview

SLI Measurement Pipeline built as a Monitoring agent. SLIs need precise definitions: which events count as good, and over what window. The pipeline ingests raw events, applies SLI definitions like successful requests over total, and emits time series for SLO evaluation. Definitions become code, not prose. Samples synthetic topic metrics for N cycles, evaluates each reading against thresholds, prints readings and alerts.

**Core concept — SLI Measurement Pipeline:** SLIs need precise definitions: which events count as good, and over what window. The pipeline ingests raw events, applies SLI definitions like successful requests over total, and emits time series for SLO evaluation. Definitions become code, not prose.

**Why this matters in the real world:** Used building SLO foundations.

---

## Features

- **Monitor**: Samples metrics, evaluates thresholds, and collects alerts.
- `read_metrics` (`read_metrics(rng, cycle)`): Sample one synthetic topic metric reading.
- `check_thresholds` (`check_thresholds(reading, thresholds)`): Return a list of alert strings for readings over threshold.
- `Monitor.run` (`Monitor.run(self, cycles, interval)`): Sample `cycles` readings, print them, return alert count.
- `main` (`main()`): Parse args and run the monitor.

## How It Works

The project is built around Periodic sampling with static threshold evaluation. Input data flows from src/main.py through the processing modules, and the overall approach runs in O(cycles) total; O(1) per sample. See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) for the high-level design and [docs/DESIGN.md](docs/DESIGN.md) for the detailed module breakdown.
