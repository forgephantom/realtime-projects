# Architecture (HLD) — Differencing for Stationarity: Simulation (Logistic Growth)

## Problem & Users

Differencing for Stationarity built as a Simulation (logistic growth). Most time-series models need stationarity (stable mean/variance): first differencing removes trends, seasonal differencing removes seasonal unit roots. Over-differencing adds noise, so the demo shows the balance. Rolling statistics visualize when stationarity is achieved. Euler-integrates logistic growth dP/dt = r*P*(1-P/K) and prints the trajectory table with summary statistics.

The intended user is a student or engineer working in computer_science (machine_learning) who needs a working, runnable reference for Differencing for Stationarity — something they can read end to end, run in seconds, and adapt to their own data or experiments.

## Data Flow

```
PARAMS (r, K, P0) + --steps/--dt -> simulate (Euler loop)
trajectory rows -> print_trajectory (sampled table)
rows -> start/end/peak summary
```

## Storage

In-memory only: the trajectory list exists for the run and is not persisted.

## Scaling & Limits

The trajectory is a plain list, so millions of steps would use noticeable memory; streaming or downsampling would fix that.

## Trade-offs

Explicit Euler is the simplest integrator to read and verify, at the cost of accuracy versus higher-order methods for stiff dynamics.

## Failure Handling

A non-positive carrying capacity K would flip the growth sign; the template documents K as positive and the default params keep it well-behaved.
