# Architecture (HLD) — Extremely Randomized Trees: Statistical Analyzer

## Problem & Users

Extremely Randomized Trees built as a Statistical analyzer. Extra Trees push randomization further than random forests: split thresholds are chosen randomly rather than optimally, making training much faster and often reducing variance more. The extra randomness can slightly increase bias, which the forest averaging usually absorbs. It is the speed-vs-precision sibling of random forests. Draws a seeded synthetic sample and reports count, mean, median, stdev, quartiles, and an ASCII histogram.

The intended user is a student or engineer working in computer_science (machine_learning) who needs a working, runnable reference for Extremely Randomized Trees — something they can read end to end, run in seconds, and adapt to their own data or experiments.

Each component maps to a real module in the project; no box in this design is aspirational — everything named here exists in the source tree.

## Data Flow

```
--seed -> generate_sample (mixture model)
sample -> summarize (sort, moments, percentiles, histogram)
summary -> print_report (table + ASCII histogram)
```

## Storage

In-memory only: the sample and summary exist for the duration of the run and nothing is persisted.

## Scaling & Limits

The sample is sorted in memory, so multi-million-point samples would need a streaming quantile sketch instead.

## Trade-offs

Hand-rolled statistics avoid dependencies but only cover univariate descriptives, not hypothesis tests or modeling.

## Failure Handling

An empty sample cannot occur (n comes from --samples), and a constant sample degrades gracefully to a single non-empty histogram bin.
