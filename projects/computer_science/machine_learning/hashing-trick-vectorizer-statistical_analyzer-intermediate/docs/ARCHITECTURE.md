# Architecture (HLD) — Hashing Trick Vectorizer: Statistical Analyzer

## Problem & Users

Hashing Trick Vectorizer built as a Statistical analyzer. The hashing trick maps tokens directly to a fixed-size vector via hashing, needing no vocabulary: memory stays constant and new words just work. Collisions add noise that signed hashing keeps unbiased. It is the streaming-friendly alternative to vocabularies. Draws a seeded synthetic sample and reports count, mean, median, stdev, quartiles, and an ASCII histogram.

The intended user is a student or engineer working in computer_science (machine_learning) who needs a working, runnable reference for Hashing Trick Vectorizer — something they can read end to end, run in seconds, and adapt to their own data or experiments.

## Data Flow

```
--seed -> generate_sample (mixture model)
sample -> summarize (sort, moments, percentiles, histogram)
summary -> print_report (table + ASCII histogram)
```

## Storage

In-memory only: the sample and summary exist for the duration of the run and nothing is persisted.

## Scaling & Limits

The sample is sorted in memory, so multi-million-point samples would need a streaming quantile sketch instead.

## Trade-offs

Hand-rolled statistics avoid dependencies but only cover univariate descriptives, not hypothesis tests or modeling.

## Failure Handling

An empty sample cannot occur (n comes from --samples), and a constant sample degrades gracefully to a single non-empty histogram bin.
