# Architecture (HLD) — k-Nearest Neighbors Classifier: Simulation (Logistic Growth)

## Problem & Users

k-Nearest Neighbors Classifier built as a Simulation (logistic growth). kNN classifies a point by majority vote of its k closest training examples: no training phase, just a distance metric and a stored dataset. Small k is noisy, large k oversmooths, and feature scaling decides what 'close' means. Its simplicity makes it the perfect first classifier to implement. Euler-integrates logistic growth dP/dt = r*P*(1-P/K) and prints the trajectory table with summary statistics.

The intended user is a student or engineer working in computer_science (machine_learning) who needs a working, runnable reference for k-Nearest Neighbors Classifier — something they can read end to end, run in seconds, and adapt to their own data or experiments.

## Data Flow

```
PARAMS (r, K, P0) + --steps/--dt -> simulate (Euler loop)
trajectory rows -> print_trajectory (sampled table)
rows -> start/end/peak summary
```

## Storage

In-memory only: the trajectory list exists for the run and is not persisted.

## Scaling & Limits

The trajectory is a plain list, so millions of steps would use noticeable memory; streaming or downsampling would fix that.

## Trade-offs

Explicit Euler is the simplest integrator to read and verify, at the cost of accuracy versus higher-order methods for stiff dynamics.

## Failure Handling

A non-positive carrying capacity K would flip the growth sign; the template documents K as positive and the default params keep it well-behaved.
