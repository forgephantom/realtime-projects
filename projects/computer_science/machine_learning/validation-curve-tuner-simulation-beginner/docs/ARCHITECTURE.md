# Architecture (HLD) — Validation Curve Tuner: Simulation (Logistic Growth)

## Problem & Users

Validation Curve Tuner built as a Simulation (logistic growth). Validation curves sweep one hyperparameter (like tree depth or regularization) plotting train vs validation score: the peak marks the sweet spot before overfitting. It isolates one knob's effect cleanly. Combined with learning curves it covers most diagnosis needs. Euler-integrates logistic growth dP/dt = r*P*(1-P/K) and prints the trajectory table with summary statistics.

The intended user is a student or engineer working in computer_science (machine_learning) who needs a working, runnable reference for Validation Curve Tuner — something they can read end to end, run in seconds, and adapt to their own data or experiments.

## Data Flow

```
PARAMS (r, K, P0) + --steps/--dt -> simulate (Euler loop)
trajectory rows -> print_trajectory (sampled table)
rows -> start/end/peak summary
```

## Storage

In-memory only: the trajectory list exists for the run and is not persisted.

## Scaling & Limits

The trajectory is a plain list, so millions of steps would use noticeable memory; streaming or downsampling would fix that.

## Trade-offs

Explicit Euler is the simplest integrator to read and verify, at the cost of accuracy versus higher-order methods for stiff dynamics.

## Failure Handling

A non-positive carrying capacity K would flip the growth sign; the template documents K as positive and the default params keep it well-behaved.
