# ANR Detector: Log Analyzer

**Domain:** computer_science | **Subdomain:** mobile_development | **Difficulty:** advanced | **Est. build time:** 8-16 hours

---

## Overview

ANR Detector built as a Log analyzer. Application Not Responding errors happen when the main thread blocks, and the detector finds the culprits. It analyzes main-thread traces attributing stalls to disk, network, or lock contention. Jank gets a name. Generates a synthetic service log in memory, parses each line with a regex, and reports level/service counts, top errors, and error rate.

**Core concept — ANR Detector:** Application Not Responding errors happen when the main thread blocks, and the detector finds the culprits. It analyzes main-thread traces attributing stalls to disk, network, or lock contention. Jank gets a name.

**Why this matters in the real world:** Used improving Android responsiveness.

---

## Features

- `generate_log` (`generate_log(seed, lines)`): Generate synthetic topic log lines in memory.
- `parse_line` (`parse_line(line)`): Parse one log line; return a dict or None if unparseable.
- `analyze` (`analyze(entries)`): Aggregate level counts, service counts, and top error messages.
- `print_report` (`print_report(report, total)`): Print the analysis report.
- `main` (`main()`): Parse args, generate, parse, and report.

## How It Works

The project is built around Regex parsing with Counter aggregation. Input data flows from src/main.py through the processing modules, and the overall approach runs in O(n) to generate, parse, and aggregate n lines. See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) for the high-level design and [docs/DESIGN.md](docs/DESIGN.md) for the detailed module breakdown.
