# Log Rotation Manager: Task Scheduler

**Domain:** computer_science | **Subdomain:** software_engineering | **Difficulty:** beginner | **Est. build time:** 2-4 hours

---

## Overview

Log Rotation Manager built as a Task scheduler. Unbounded logs fill disks: the rotation manager rolls files by size or time, compresses archives, and prunes beyond retention, all without losing in-flight writes. It coordinates with the logger via reopen signals. Disk-full outages are the failure it prevents. Registers interval jobs on a heap scheduler, runs them for a fixed demo duration, and prints the execution log.

**Core concept — Log Rotation Manager:** Unbounded logs fill disks: the rotation manager rolls files by size or time, compresses archives, and prunes beyond retention, all without losing in-flight writes. It coordinates with the logger via reopen signals. Disk-full outages are the failure it prevents.

**Why this matters in the real world:** logrotate and built-in rotating handlers manage log disk usage.

---

## Features

- **Scheduler**: Minimal interval scheduler driven by a heap of next-run times.
- `make_demo_job` (`make_demo_job(tag)`): Build a demo job function that counts its own executions.
- `Scheduler.add_job` (`Scheduler.add_job(self, name, interval, func)`): Register `func` to run every `interval` seconds under `name`.
- `Scheduler.run` (`Scheduler.run(self, duration)`): Run scheduled jobs for `duration` seconds; return the log.
- `main` (`main()`): Parse args, register demo jobs, run, and print the log.

## How It Works

The project is built around Heap-ordered next-run-time scheduling loop. Input data flows from src/main.py through the processing modules, and the overall approach runs in O(log j) per execution for j jobs. See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) for the high-level design and [docs/DESIGN.md](docs/DESIGN.md) for the detailed module breakdown.
