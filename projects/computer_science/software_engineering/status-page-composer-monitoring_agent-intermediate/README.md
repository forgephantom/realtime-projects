# Status Page Composer: Monitoring Agent

**Domain:** computer_science | **Subdomain:** software_engineering | **Difficulty:** intermediate | **Est. build time:** 4-8 hours

---

## Overview

Status Page Composer built as a Monitoring agent. Status pages communicate incidents: the composer aggregates component health, posts incident updates with severity and ETA, and maintains history. Templates keep updates consistent under stress. Honest, frequent updates are the product. Samples synthetic topic metrics for N cycles, evaluates each reading against thresholds, prints readings and alerts.

**Core concept — Status Page Composer:** Status pages communicate incidents: the composer aggregates component health, posts incident updates with severity and ETA, and maintains history. Templates keep updates consistent under stress. Honest, frequent updates are the product.

**Why this matters in the real world:** Atlassian Statuspage and in-house status pages communicate reliability.

---

## Features

- **Monitor**: Samples metrics, evaluates thresholds, and collects alerts.
- `read_metrics` (`read_metrics(rng, cycle)`): Sample one synthetic topic metric reading.
- `check_thresholds` (`check_thresholds(reading, thresholds)`): Return a list of alert strings for readings over threshold.
- `Monitor.run` (`Monitor.run(self, cycles, interval)`): Sample `cycles` readings, print them, return alert count.
- `main` (`main()`): Parse args and run the monitor.

## How It Works

The project is built around Periodic sampling with static threshold evaluation. Input data flows from src/main.py through the processing modules, and the overall approach runs in O(cycles) total; O(1) per sample. See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) for the high-level design and [docs/DESIGN.md](docs/DESIGN.md) for the detailed module breakdown.
