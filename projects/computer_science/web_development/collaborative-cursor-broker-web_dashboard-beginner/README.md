# Collaborative Cursor Broker: Web Dashboard

**Domain:** computer_science | **Subdomain:** web_development | **Difficulty:** beginner | **Est. build time:** 2-4 hours

---

## Overview

Collaborative Cursor Broker built as a Web dashboard. Shared cursors show where collaborators are: the broker relays cursor positions and selections per document at throttled rates, assigns deterministic colors per user, and removes cursors on disconnect. Positions reference document versions so they stay meaningful during concurrent edits. It is presence applied to a document. Serves a single-page HTML dashboard of topic metrics plus a JSON metrics endpoint.

**Core concept — Collaborative Cursor Broker:** Shared cursors show where collaborators are: the broker relays cursor positions and selections per document at throttled rates, assigns deterministic colors per user, and removes cursors on disconnect. Positions reference document versions so they stay meaningful during concurrent edits. It is presence applied to a document.

**Why this matters in the real world:** Google Docs, Figma, and Notion all broadcast collaborator cursors over realtime channels.

---

## Features

- **DashboardHandler**: Serves the dashboard HTML page and a JSON metrics endpoint.
- `metric_rows` (`metric_rows(seed, count)`): Generate deterministic synthetic metric rows.
- `render_page` (`render_page(seed, count)`): Render the full dashboard HTML page.
- `start_server` (`start_server(port, seed, count)`): Bind a ThreadingHTTPServer on 127.0.0.1 and serve it in a thread.
- `run_self_test` (`run_self_test(base_url, seed, count)`): Fetch the page and metrics endpoint; print a verification summary.
- `main` (`main()`): Parse args; self-test by default or serve with --serve.

## How It Works

The project is built around Server-side HTML rendering of a metrics table. Input data flows from src/main.py through the processing modules, and the overall approach runs in O(n) to render n metric rows. See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) for the high-level design and [docs/DESIGN.md](docs/DESIGN.md) for the detailed module breakdown.
