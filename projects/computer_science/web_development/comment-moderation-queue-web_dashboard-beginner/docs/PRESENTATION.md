# Presentation Guide — Comment Moderation Queue: Web Dashboard

## 60-Second Pitch

A zero-dependency Comment Moderation Queue dashboard that renders live metrics as HTML and JSON, verified end to end by its own self-test. User comments need review at scale: the queue auto-approves trusted users, holds suspicious content (links, blocklisted words, rapid posting) for moderators, and learns from moderator decisions.

Comment Moderation Queue in two sentences: User comments need review at scale: the queue auto-approves trusted users, holds suspicious content (links, blocklisted words, rapid posting) for moderators, and learns from moderator decisions. SLA timers escalate stale items, and audit trails record every decision. The balance is safety without strangling conversation.

## Architecture Talking Points

- Components: `DashboardHandler` plus the CLI entrypoint — each maps to a real module in `src/`, and the data-flow diagram shows how they connect.
- Algorithm: Server-side HTML rendering of a metrics table; runs in O(n) to render n metric rows.
- Honest scaling limit: Single-process threaded server rendering small pages; fine for local demos, not for high-traffic or large metric sets.

Use these when someone asks "how does it work?" — start with the problem, then walk the data flow, then name one trade-off. Trade-offs are what interviewers remember.

## Interview Q&A

**Q:** Does the page need JavaScript?

**A:** No; the table is rendered server-side as plain HTML, with a meta refresh tag for periodic updates.

**Q:** Where do the metrics come from?

**A:** A seeded RNG generates deterministic synthetic rows, so the dashboard is reproducible without any external data source.

**Q:** Can it serve persistently?

**A:** Yes, pass --serve to keep the ThreadingHTTPServer running on 127.0.0.1 until interrupted.
