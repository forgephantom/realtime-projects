# Architecture (HLD) — GraphQL Query Planner (Lite): Simulation (Logistic Growth)

## Problem & Users

GraphQL Query Planner (Lite) built as a Simulation (logistic growth). GraphQL lets clients ask for exactly the fields they need: the planner parses queries into an AST, validates them against the schema (types, arguments, depth limits), and plans batched resolver execution to avoid N+1 fetches. Query complexity scoring rejects abusive queries before execution. The planner is what makes 'ask for anything' safe. Euler-integrates logistic growth dP/dt = r*P*(1-P/K) and prints the trajectory table with summary statistics.

The intended user is a student or engineer working in computer_science (web_development) who needs a working, runnable reference for GraphQL Query Planner (Lite) — something they can read end to end, run in seconds, and adapt to their own data or experiments.

## Data Flow

```
PARAMS (r, K, P0) + --steps/--dt -> simulate (Euler loop)
trajectory rows -> print_trajectory (sampled table)
rows -> start/end/peak summary
```

## Storage

In-memory only: the trajectory list exists for the run and is not persisted.

## Scaling & Limits

The trajectory is a plain list, so millions of steps would use noticeable memory; streaming or downsampling would fix that.

## Trade-offs

Explicit Euler is the simplest integrator to read and verify, at the cost of accuracy versus higher-order methods for stiff dynamics.

## Failure Handling

A non-positive carrying capacity K would flip the growth sign; the template documents K as positive and the default params keep it well-behaved.
