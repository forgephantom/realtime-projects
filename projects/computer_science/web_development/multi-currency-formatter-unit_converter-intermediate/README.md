**Domain:** computer_science | **Subdomain:** web_development | **Difficulty:** intermediate | **Est. build time:** 4-8 hours

## Overview

Multi-Currency Formatter built as a unit converter. Money formatting is locale-specific: the formatter applies currency symbols or codes, decimal and grouping separators, and per-currency minor-unit rules (JPY has no cents). It converts with explicit rates and timestamps, never silently. Rounding mode on conversion is a financial decision, not a default. A unit converter covering length, mass, volume, speed, data sizes, and temperature, with real conversion factors and offset-aware temperature math.

**Core concept — Multi-Currency Formatter:** Money formatting is locale-specific: the formatter applies currency symbols or codes, decimal and grouping separators, and per-currency minor-unit rules (JPY has no cents). It converts with explicit rates and timestamps, never silently. Rounding mode on conversion is a financial decision, not a default.

**Why this matters in the real world:** Stripe, Wise, and every international checkout format and convert currencies with explicit rounding.

## Features

- **UnitConverter**: Converts between units within a category using factor tables; temperature is offset-aware.
- `UnitConverter.convert` (`convert(self, value: float, from_unit: str, to_unit: str) -> float`): Convert value from from_unit to to_unit; raises ValueError on misuse.
- `UnitConverter.categories` (`categories(self) -> list`): Category names, including temperature.
- `UnitConverter.units` (`units(self, category: str) -> list`): Unit names for a category.
- `run_demo` (`run_demo(seed: int) -> int`): Convert the seeded demo list and print a results table.
- `run_single` (`run_single(value: float, from_unit: str, to_unit: str) -> int`): Convert one value supplied on the command line.
- `build_parser` (`build_parser() -> argparse.ArgumentParser`): Build the command-line parser for the demo.
- `main` (`main(argv=None) -> int`): Demo table by default; single conversion with --value/--from/--to.

## How It Works

The project is built around Factor-to-base-unit tables; temperature via to/from-Celsius functions. Input data flows from src/main.py through the processing modules, and the overall approach runs in O(1) per conversion. See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) for the high-level design and [docs/DESIGN.md](docs/DESIGN.md) for the detailed module breakdown.
