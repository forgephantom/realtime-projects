# Optimistic UI Conflict Resolver: Web Dashboard

**Domain:** computer_science | **Subdomain:** web_development | **Difficulty:** intermediate | **Est. build time:** 4-8 hours

---

## Overview

Optimistic UI Conflict Resolver built as a Web dashboard. Optimistic UI applies changes instantly and reconciles with the server after: the resolver tracks pending mutations, rolls back on server rejection, and merges when the server state moved underneath. Version vectors or etags detect the conflicts. Done well, apps feel instant; done poorly, user edits vanish mysteriously. Serves a single-page HTML dashboard of topic metrics plus a JSON metrics endpoint.

**Core concept — Optimistic UI Conflict Resolver:** Optimistic UI applies changes instantly and reconciles with the server after: the resolver tracks pending mutations, rolls back on server rejection, and merges when the server state moved underneath. Version vectors or etags detect the conflicts. Done well, apps feel instant; done poorly, user edits vanish mysteriously.

**Why this matters in the real world:** Linear, Notion, and mobile apps use optimistic updates with rollback for perceived performance.

---

## Features

- **DashboardHandler**: Serves the dashboard HTML page and a JSON metrics endpoint.
- `metric_rows` (`metric_rows(seed, count)`): Generate deterministic synthetic metric rows.
- `render_page` (`render_page(seed, count)`): Render the full dashboard HTML page.
- `start_server` (`start_server(port, seed, count)`): Bind a ThreadingHTTPServer on 127.0.0.1 and serve it in a thread.
- `run_self_test` (`run_self_test(base_url, seed, count)`): Fetch the page and metrics endpoint; print a verification summary.
- `main` (`main()`): Parse args; self-test by default or serve with --serve.

## How It Works

The project is built around Server-side HTML rendering of a metrics table. Input data flows from src/main.py through the processing modules, and the overall approach runs in O(n) to render n metric rows. See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) for the high-level design and [docs/DESIGN.md](docs/DESIGN.md) for the detailed module breakdown.
