# Architecture (HLD) — Remember-Me Token Rotation: Simulation (Logistic Growth)

## Problem & Users

Remember-Me Token Rotation built as a Simulation (logistic growth). Remember-me cookies trade convenience for risk, so secure designs use rotating token series: a persistent series id plus a one-time token, where each use issues a fresh token and invalidates the old one. If a stolen token is replayed, the series mismatch reveals theft and the whole series is revoked. This gives long-lived login with theft detection built in. Euler-integrates logistic growth dP/dt = r*P*(1-P/K) and prints the trajectory table with summary statistics.

The intended user is a student or engineer working in computer_science (web_development) who needs a working, runnable reference for Remember-Me Token Rotation — something they can read end to end, run in seconds, and adapt to their own data or experiments.

## Data Flow

```
PARAMS (r, K, P0) + --steps/--dt -> simulate (Euler loop)
trajectory rows -> print_trajectory (sampled table)
rows -> start/end/peak summary
```

## Storage

In-memory only: the trajectory list exists for the run and is not persisted.

## Scaling & Limits

The trajectory is a plain list, so millions of steps would use noticeable memory; streaming or downsampling would fix that.

## Trade-offs

Explicit Euler is the simplest integrator to read and verify, at the cost of accuracy versus higher-order methods for stiff dynamics.

## Failure Handling

A non-positive carrying capacity K would flip the growth sign; the template documents K as positive and the default params keep it well-behaved.
