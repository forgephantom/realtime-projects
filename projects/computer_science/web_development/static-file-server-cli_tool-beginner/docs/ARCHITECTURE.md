# Architecture (HLD) — Static File Server with Conditional Requests: Command-Line Tool

## Problem & Users

Static File Server with Conditional Requests built as a Command-line tool. A static file server maps URL paths to files on disk and serves them with the right content type, but it can avoid resending unchanged files using conditional requests. ETags and Last-Modified headers let clients send If-None-Match, so the server answers 304 Not Modified instead of the full body. This single mechanism cuts bandwidth dramatically for assets that rarely change. A subcommand CLI that generates seeded synthetic topic rows and reports summaries, top-N rows, or filtered rows as tables or JSON.

The intended user is a student or engineer working in computer_science (web_development) who needs a working, runnable reference for Static File Server with Conditional Requests — something they can read end to end, run in seconds, and adapt to their own data or experiments.

## Data Flow

```
--seed -> generate_rows (synthetic table)
subcommand: summary | top | filter -> formatted table or JSON
```

## Storage

No persistence: rows are regenerated from the seed on every invocation and nothing is written to disk.

## Scaling & Limits

Rows live in a Python list, so memory grows linearly with --rows; fine for tens of thousands of rows on a laptop.

## Trade-offs

Synthetic seeded data keeps the tool self-contained and reproducible, at the cost of not reading real input files.

## Failure Handling

An empty filter result prints a zero-count table rather than erroring; --top-n larger than the row count simply returns all rows.
