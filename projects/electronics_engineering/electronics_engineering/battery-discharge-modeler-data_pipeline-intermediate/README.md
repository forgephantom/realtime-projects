# Battery Discharge Modeler: Data Pipeline (Etl)

**Domain:** electronics_engineering | **Subdomain:** electronics_engineering | **Difficulty:** intermediate | **Est. build time:** 4-8 hours

---

## Overview

Battery Discharge Modeler built as a Data pipeline (ETL). A battery's runtime is roughly its milliamp-hour rating divided by the load current, but internal resistance makes the terminal voltage sag as current rises. Modeling voltage over time shows why a battery reads full at rest yet droops under heavy load. Extracts synthetic topic records, transforms them (drop invalid, normalize, bucket), and loads the clean set to CSV.

**Core concept — Battery Discharge Modeler:** A battery's runtime is roughly its milliamp-hour rating divided by the load current, but internal resistance makes the terminal voltage sag as current rises. Modeling voltage over time shows why a battery reads full at rest yet droops under heavy load.

**Why this matters in the real world:** Wearables, remote sensors, and power tools are all sized with discharge models like this before battery selection.

---

## Features

- **Pipeline**: Three-stage ETL pipeline for topic records.
- `generate_raw` (`generate_raw(seed, n)`): Extract stage: build synthetic raw records.
- `clean_rows` (`clean_rows(rows)`): Transform stage: drop invalid rows, normalize, bucket. Returns (clean_rows, dropped_count).
- `write_csv` (`write_csv(path, rows)`): Load stage: write rows to a CSV file.
- `Pipeline.extract` (`Pipeline.extract(self, n)`): Run the extract stage and return raw rows.
- `Pipeline.transform` (`Pipeline.transform(self, rows)`): Run the transform stage and return (clean, dropped).
- `Pipeline.load` (`Pipeline.load(self, rows)`): Run the load stage; return the CSV path written.
- `Pipeline.run` (`Pipeline.run(self, n)`): Run extract -> transform -> load; print a stage report.
- `main` (`main()`): Parse args and run the pipeline.

## How It Works

The project is built around Extract -> transform -> load over synthetic records. Input data flows from src/main.py through the processing modules, and the overall approach runs in O(n) across all three stages. See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) for the high-level design and [docs/DESIGN.md](docs/DESIGN.md) for the detailed module breakdown.

## How to Run

```

python3 src/main.py --help
python3 src/main.py
```
