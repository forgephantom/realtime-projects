# CAN Bus Load Analyzer: Log Analyzer

**Domain:** electronics_engineering | **Subdomain:** electronics_engineering | **Difficulty:** intermediate | **Est. build time:** 4-8 hours

---

## Overview

CAN Bus Load Analyzer built as a Log analyzer. CAN bus load is the fraction of bit time consumed by frames, computed from message IDs, payload lengths, and periods, and keeping it under about 70 percent leaves headroom for error frames. Generates a synthetic service log in memory, parses each line with a regex, and reports level/service counts, top errors, and error rate.

**Core concept — CAN Bus Load Analyzer:** CAN bus load is the fraction of bit time consumed by frames, computed from message IDs, payload lengths, and periods, and keeping it under about 70 percent leaves headroom for error frames.

**Why this matters in the real world:** Used in automotive network design to validate that a CAN database fits the bitrate.

---

## Features

- `generate_log` (`generate_log(seed, lines)`): Generate synthetic topic log lines in memory.
- `parse_line` (`parse_line(line)`): Parse one log line; return a dict or None if unparseable.
- `analyze` (`analyze(entries)`): Aggregate level counts, service counts, and top error messages.
- `print_report` (`print_report(report, total)`): Print the analysis report.
- `main` (`main()`): Parse args, generate, parse, and report.

## How It Works

The project is built around Regex parsing with Counter aggregation. Input data flows from src/main.py through the processing modules, and the overall approach runs in O(n) to generate, parse, and aggregate n lines. See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) for the high-level design and [docs/DESIGN.md](docs/DESIGN.md) for the detailed module breakdown.
