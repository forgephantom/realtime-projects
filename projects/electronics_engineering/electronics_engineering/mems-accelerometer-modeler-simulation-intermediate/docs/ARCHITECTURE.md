# Architecture (HLD) — MEMS Accelerometer Modeler: Simulation (Logistic Growth)

## Problem & Users

MEMS Accelerometer Modeler built as a Simulation (logistic growth). A MEMS accelerometer is a microscopic spring-mass system whose resonant frequency and damping set its bandwidth and noise floor. The modeler computes sensitivity, bandwidth, and Brownian noise from the proof-mass and spring geometry. Euler-integrates logistic growth dP/dt = r*P*(1-P/K) and prints the trajectory table with summary statistics.

The intended user is a student or engineer working in electronics_engineering (electronics_engineering) who needs a working, runnable reference for MEMS Accelerometer Modeler — something they can read end to end, run in seconds, and adapt to their own data or experiments.

## Data Flow

```
PARAMS (r, K, P0) + --steps/--dt -> simulate (Euler loop)
trajectory rows -> print_trajectory (sampled table)
rows -> start/end/peak summary
```

## Storage

In-memory only: the trajectory list exists for the run and is not persisted.

## Scaling & Limits

The trajectory is a plain list, so millions of steps would use noticeable memory; streaming or downsampling would fix that.

## Trade-offs

Explicit Euler is the simplest integrator to read and verify, at the cost of accuracy versus higher-order methods for stiff dynamics.

## Failure Handling

A non-positive carrying capacity K would flip the growth sign; the template documents K as positive and the default params keep it well-behaved.
