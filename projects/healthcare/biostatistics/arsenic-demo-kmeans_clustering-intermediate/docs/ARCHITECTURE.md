# Architecture (HLD) — Arsenic Demo (Synthetic): K-Means Clustering

## Problem & Users

Arsenic Demo (Synthetic) built as a K-means clustering. An arsenic teacher mapping synthetic well contamination with from-scratch methods across fictional villages. Wells are fictional. Runs Lloyd's k-means on seeded 2-D synthetic points and prints final centroids, cluster sizes, and inertia.

The intended user is a student or engineer working in healthcare (biostatistics) who needs a working, runnable reference for Arsenic Demo (Synthetic) — something they can read end to end, run in seconds, and adapt to their own data or experiments.

## Data Flow

```
--seed -> generate_points (k Gaussian blobs)
points -> kmeans: assign -> recompute -> ...
(centroids, labels) -> inertia + cluster table
```

## Storage

In-memory only: points, centroids, and labels exist for the run and are not persisted.

## Scaling & Limits

Pure-Python distance loops are O(n*k) per iteration, so large datasets would need numpy vectorization.

## Trade-offs

Hand-written Lloyd's is transparent and dependency-free, but lacks k-means++ seeding and mini-batch variants for big data.

## Failure Handling

An empty cluster keeps its previous centroid instead of producing NaNs; iteration stops early when centroids stop moving.
