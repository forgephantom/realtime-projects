# Architecture (HLD) — Primer Tm Estimator: Statistical Analyzer

## Problem & Users

Primer Tm Estimator built as a Statistical analyzer. Melting temperature predicts when a PCR primer anneals: the Wallace rule gives a quick estimate while nearest-neighbor thermodynamics accounts for stacking interactions and salt concentration. Matched Tm values across primer pairs keep them annealing together. Synthetic primers with computed values let developers compare methods. Draws a seeded synthetic sample and reports count, mean, median, stdev, quartiles, and an ASCII histogram.

The intended user is a student or engineer working in healthcare (genomics) who needs a working, runnable reference for Primer Tm Estimator — something they can read end to end, run in seconds, and adapt to their own data or experiments.

| Component | Module | Responsibility |

Each component maps to a real module in the project; no box in this design is aspirational — everything named here exists in the source tree.

## Data Flow

```
--seed -> generate_sample (mixture model)
sample -> summarize (sort, moments, percentiles, histogram)
summary -> print_report (table + ASCII histogram)
```

## Storage

In-memory only: the sample and summary exist for the duration of the run and nothing is persisted.

## Scaling & Limits

The sample is sorted in memory, so multi-million-point samples would need a streaming quantile sketch instead.

## Trade-offs

Hand-rolled statistics avoid dependencies but only cover univariate descriptives, not hypothesis tests or modeling.

## Failure Handling

An empty sample cannot occur (n comes from --samples), and a constant sample degrades gracefully to a single non-empty histogram bin.
