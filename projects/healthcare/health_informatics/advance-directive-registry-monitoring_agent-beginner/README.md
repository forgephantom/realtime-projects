# Advance Directive Registry (Demo): Monitoring Agent

**Domain:** healthcare | **Subdomain:** health_informatics | **Difficulty:** beginner | **Est. build time:** 2-4 hours

---

## Overview

Advance Directive Registry (Demo) built as a Monitoring agent. A document registry demo tracking synthetic advance directives with type, execution date, witness status, and surrogate contacts. It flags documents needing review after major health events in the fictional timeline. All persons are fictional and the tool gives no legal advice. Samples synthetic topic metrics for N cycles, evaluates each reading against thresholds, prints readings and alerts.

**Core concept — Advance Directive Registry (Demo):** A document registry demo tracking synthetic advance directives with type, execution date, witness status, and surrogate contacts. It flags documents needing review after major health events in the fictional timeline. All persons are fictional and the tool gives no legal advice.

**Why this matters in the real world:** Used in advance-care-planning education.

---

## Features

- **Monitor**: Samples metrics, evaluates thresholds, and collects alerts.
- `read_metrics` (`read_metrics(rng, cycle)`): Sample one synthetic topic metric reading.
- `check_thresholds` (`check_thresholds(reading, thresholds)`): Return a list of alert strings for readings over threshold.
- `Monitor.run` (`Monitor.run(self, cycles, interval)`): Sample `cycles` readings, print them, return alert count.
- `main` (`main()`): Parse args and run the monitor.

## How It Works

The project is built around Periodic sampling with static threshold evaluation. Input data flows from src/main.py through the processing modules, and the overall approach runs in O(cycles) total; O(1) per sample. See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) for the high-level design and [docs/DESIGN.md](docs/DESIGN.md) for the detailed module breakdown.
