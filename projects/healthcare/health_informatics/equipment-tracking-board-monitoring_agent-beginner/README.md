# Medical Equipment Tracking Board: Monitoring Agent

**Domain:** healthcare | **Subdomain:** health_informatics | **Difficulty:** beginner | **Est. build time:** 2-4 hours

---

## Overview

Medical Equipment Tracking Board built as a Monitoring agent. An asset-location board for synthetic mobile equipment like infusion pumps and wheelchairs, tracking which unit holds each item and its clean or dirty status. It flags units hoarding equipment and lists items due for preventive maintenance. All assets are fictional. Samples synthetic topic metrics for N cycles, evaluates each reading against thresholds, prints readings and alerts.

**Core concept — Medical Equipment Tracking Board:** An asset-location board for synthetic mobile equipment like infusion pumps and wheelchairs, tracking which unit holds each item and its clean or dirty status. It flags units hoarding equipment and lists items due for preventive maintenance. All assets are fictional.

**Why this matters in the real world:** Used by clinical engineering demonstrating asset-tracking workflows.

---

## Features

- **Monitor**: Samples metrics, evaluates thresholds, and collects alerts.
- `read_metrics` (`read_metrics(rng, cycle)`): Sample one synthetic topic metric reading.
- `check_thresholds` (`check_thresholds(reading, thresholds)`): Return a list of alert strings for readings over threshold.
- `Monitor.run` (`Monitor.run(self, cycles, interval)`): Sample `cycles` readings, print them, return alert count.
- `main` (`main()`): Parse args and run the monitor.

## How It Works

The project is built around Periodic sampling with static threshold evaluation. Input data flows from src/main.py through the processing modules, and the overall approach runs in O(cycles) total; O(1) per sample. See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) for the high-level design and [docs/DESIGN.md](docs/DESIGN.md) for the detailed module breakdown.
