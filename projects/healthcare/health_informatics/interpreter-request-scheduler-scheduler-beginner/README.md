# Interpreter Request Scheduler: Task Scheduler

**Domain:** healthcare | **Subdomain:** health_informatics | **Difficulty:** beginner | **Est. build time:** 2-4 hours

---

## Overview

Interpreter Request Scheduler built as a Task scheduler. A language-services dispatcher that matches interpreter requests to available interpreters by language, modality, and time window. It prioritizes urgent clinical requests and reports unfilled requests per language. The schedule view shows each interpreter's booked blocks. Registers interval jobs on a heap scheduler, runs them for a fixed demo duration, and prints the execution log.

**Core concept — Interpreter Request Scheduler:** A language-services dispatcher that matches interpreter requests to available interpreters by language, modality, and time window. It prioritizes urgent clinical requests and reports unfilled requests per language. The schedule view shows each interpreter's booked blocks.

**Why this matters in the real world:** Used by hospital language-access offices to staff interpreters across departments.

---

## Features

- **Scheduler**: Minimal interval scheduler driven by a heap of next-run times.
- `make_demo_job` (`make_demo_job(tag)`): Build a demo job function that counts its own executions.
- `Scheduler.add_job` (`Scheduler.add_job(self, name, interval, func)`): Register `func` to run every `interval` seconds under `name`.
- `Scheduler.run` (`Scheduler.run(self, duration)`): Run scheduled jobs for `duration` seconds; return the log.
- `main` (`main()`): Parse args, register demo jobs, run, and print the log.

## How It Works

The project is built around Heap-ordered next-run-time scheduling loop. Input data flows from src/main.py through the processing modules, and the overall approach runs in O(log j) per execution for j jobs. See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) for the high-level design and [docs/DESIGN.md](docs/DESIGN.md) for the detailed module breakdown.
