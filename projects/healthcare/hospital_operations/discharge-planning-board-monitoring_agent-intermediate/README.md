# Discharge Planning Board: Monitoring Agent

**Domain:** healthcare | **Subdomain:** hospital_operations | **Difficulty:** intermediate | **Est. build time:** 4-8 hours

---

## Overview

Discharge Planning Board built as a Monitoring agent. Discharge planning boards track each patient's readiness: pending tests, consults, prescriptions, and post-discharge placement. Delays in any item push discharge later, blocking the bed for incoming patients. Synthetic patient records with known pending items verify the readiness logic. Samples synthetic topic metrics for N cycles, evaluates each reading against thresholds, prints readings and alerts.

**Core concept — Discharge Planning Board:** Discharge planning boards track each patient's readiness: pending tests, consults, prescriptions, and post-discharge placement. Delays in any item push discharge later, blocking the bed for incoming patients. Synthetic patient records with known pending items verify the readiness logic.

**Why this matters in the real world:** Discharge boards accelerate safe discharges and free beds sooner.

---

## Features

- **Monitor**: Samples metrics, evaluates thresholds, and collects alerts.
- `read_metrics` (`read_metrics(rng, cycle)`): Sample one synthetic topic metric reading.
- `check_thresholds` (`check_thresholds(reading, thresholds)`): Return a list of alert strings for readings over threshold.
- `Monitor.run` (`Monitor.run(self, cycles, interval)`): Sample `cycles` readings, print them, return alert count.
- `main` (`main()`): Parse args and run the monitor.

## How It Works

The project is built around Periodic sampling with static threshold evaluation. Input data flows from src/main.py through the processing modules, and the overall approach runs in O(cycles) total; O(1) per sample. See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) for the high-level design and [docs/DESIGN.md](docs/DESIGN.md) for the detailed module breakdown.
