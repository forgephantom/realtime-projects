# Architecture (HLD) — CT Slice Phantom Simulator: Imaging_Analyzer

## Problem & Users

CT Slice Phantom Simulator built as a imaging_analyzer. CT images encode X-ray attenuation on the Hounsfield scale, where air sits near -1000 and dense bone near +1000. A software phantom assigns each material region a representative attenuation value and renders a slice, optionally adding noise. Comparing algorithm output against the known phantom reveals exactly where a pipeline drifts. A synthetic scan analyzer that generates a seeded 2D scan with an anomalous blob, segments it by thresholding, and reports the blob centroid and size.

The intended user is a student or engineer working in healthcare (medical_imaging) who needs a working, runnable reference for CT Slice Phantom Simulator — something they can read end to end, run in seconds, and adapt to their own data or experiments.

## Data Flow

```
seed -> generate_scan (background + anomaly blob) -> grid
 grid -> region_stats -> mean, stdev, min, max
mean + 2*stdev -> threshold -> segment -> binary mask
mask -> connected_components (BFS) -> largest blob -> centroid, size
```

## Storage

No persistence: the scan is regenerated from the seed each run.

## Scaling & Limits

Pixel loops suit demo resolutions; megapixel scans would want numpy or tiled processing.

## Trade-offs

A global threshold is simple and fast but can miss faint anomalies that adaptive methods would catch.

## Failure Handling

If no pixel clears the threshold, the report says no anomaly was found instead of crashing on an empty mask.
