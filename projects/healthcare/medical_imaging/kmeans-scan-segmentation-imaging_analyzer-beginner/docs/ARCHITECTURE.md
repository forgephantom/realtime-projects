# Architecture (HLD) — K-Means Scan Segmentation: Imaging_Analyzer

## Problem & Users

K-Means Scan Segmentation built as a imaging_analyzer. K-means clustering groups pixels by intensity, optionally including spatial coordinates, into a fixed number of tissue classes. Random initialization makes results vary, so multiple restarts with the best inertia are standard practice. Cluster purity against known phantom labels shows how well the unsupervised split matches real tissue boundaries. A synthetic scan analyzer that generates a seeded 2D scan with an anomalous blob, segments it by thresholding, and reports the blob centroid and size.

The intended user is a student or engineer working in healthcare (medical_imaging) who needs a working, runnable reference for K-Means Scan Segmentation — something they can read end to end, run in seconds, and adapt to their own data or experiments.

## Data Flow

```
seed -> generate_scan (background + anomaly blob) -> grid
 grid -> region_stats -> mean, stdev, min, max
mean + 2*stdev -> threshold -> segment -> binary mask
mask -> connected_components (BFS) -> largest blob -> centroid, size
```

## Storage

No persistence: the scan is regenerated from the seed each run.

## Scaling & Limits

Pixel loops suit demo resolutions; megapixel scans would want numpy or tiled processing.

## Trade-offs

A global threshold is simple and fast but can miss faint anomalies that adaptive methods would catch.

## Failure Handling

If no pixel clears the threshold, the report says no anomaly was found instead of crashing on an empty mask.
