# Architecture (HLD) — Fixed-Point Iterator: Command-Line Tool

## Problem & Users

Fixed-Point Iterator built as a Command-line tool. Fixed-point iteration solves x = g(x) by repeated substitution, converging when g is a contraction with slope magnitude below 1 near the fixed point. The contraction mapping theorem guarantees a unique attractive fixed point in that case. The iterator detects divergence and oscillation automatically. A subcommand CLI that generates seeded synthetic topic rows and reports summaries, top-N rows, or filtered rows as tables or JSON.

The intended user is a student or engineer working in mathematics (mathematics) who needs a working, runnable reference for Fixed-Point Iterator — something they can read end to end, run in seconds, and adapt to their own data or experiments.

| Component | Module | Responsibility |

Each component maps to a real module in the project; no box in this design is aspirational — everything named here exists in the source tree.

## Data Flow

```
--seed -> generate_rows (synthetic table)
subcommand: summary | top | filter -> formatted table or JSON
```

## Storage

No persistence: rows are regenerated from the seed on every invocation and nothing is written to disk.

## Scaling & Limits

Rows live in a Python list, so memory grows linearly with --rows; fine for tens of thousands of rows on a laptop.

## Trade-offs

Synthetic seeded data keeps the tool self-contained and reproducible, at the cost of not reading real input files.

## Failure Handling

An empty filter result prints a zero-count table rather than erroring; --top-n larger than the row count simply returns all rows.
