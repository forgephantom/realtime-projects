# Architecture (HLD) — Portfolio Variance Optimizer: Statistical Analyzer

## Problem & Users

Portfolio Variance Optimizer built as a Statistical analyzer. Portfolio variance combines asset variances with pairwise covariances weighted by holdings; diversification works when correlations are below one. The minimum-variance portfolio has a closed-form solution under a budget constraint. The optimizer computes the efficient frontier for two-asset blends and reports the tangency weights. Draws a seeded synthetic sample and reports count, mean, median, stdev, quartiles, and an ASCII histogram.

The intended user is a student or engineer working in mathematics (mathematics) who needs a working, runnable reference for Portfolio Variance Optimizer — something they can read end to end, run in seconds, and adapt to their own data or experiments.

## Data Flow

```
--seed -> generate_sample (mixture model)
sample -> summarize (sort, moments, percentiles, histogram)
summary -> print_report (table + ASCII histogram)
```

## Storage

In-memory only: the sample and summary exist for the duration of the run and nothing is persisted.

## Scaling & Limits

The sample is sorted in memory, so multi-million-point samples would need a streaming quantile sketch instead.

## Trade-offs

Hand-rolled statistics avoid dependencies but only cover univariate descriptives, not hypothesis tests or modeling.

## Failure Handling

An empty sample cannot occur (n comes from --samples), and a constant sample degrades gracefully to a single non-empty histogram bin.
